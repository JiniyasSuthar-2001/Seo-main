# AI WORKING GUIDELINES — SEO DASHBOARD

This rule set defines the non-negotiable operational guidelines for all AI features, prompts, and models in the SEO Intelligence Platform.

## 1. AI IS AN ANALYST, NOT THE SOURCE OF SEO DATA
AI must never invent SEO data.
The source of truth is:
* Real website crawler data
* Real SEO audit results
* Google Search Console data
* Real ranking-data providers
* Real SERP data
* Real backlink data
* Real competitor data
* Real keyword data
* User-imported CSV data

AI only analyzes, explains, prioritizes, compares, and recommends actions based on available data.

## 2. NEVER FABRICATE DATA
Never invent keyword rankings, search volume, traffic, CTR, impressions, backlinks, competitors, competitor rankings, domain authority, keyword difficulty, SEO scores, crawl results, or algorithm updates.
If data is unavailable, explicitly state: **"Data unavailable"**.

## 3. ALWAYS SEPARATE FACTS FROM AI SUGGESTIONS
Every AI response must distinguish between:
- **Actual Data**: Information directly obtained from the SEO data layer.
- **AI Analysis**: Interpretation of the actual data.
- **AI Recommendation**: Suggested action based on analysis.
- **AI Suggestion**: Ideas generated by AI that are not directly measured. Label clearly as **"AI Suggested"**.

## 4. ALWAYS USE EVIDENCE
Every important recommendation must reference the evidence behind it, formatted as:
`Issue` -> `Evidence` -> `Why it matters` -> `Recommended action` -> `Priority` -> `Affected URL`.

## 5. DO NOT REPLACE THE DETERMINISTIC SEO ENGINE
Technical SEO checks (HTTP status codes, missing title, missing H1, broken links, canonicals, indexability, word count) remain 100% deterministic in the crawler/audit engine. AI explains these findings without changing their factual result.

## 6. ANALYZE REAL KEYWORD DATA
When keyword data exists, AI analyzes search intent, relevance, opportunities, and content gaps. If ranking data does not exist, AI must never invent ranking positions.

## 7. ANALYZE REAL COMPETITOR DATA
Competitors must come from verified evidence (outbound links, SERP data, user input). AI must never invent competitor domains or businesses.

## 8. DO NOT CLAIM CAUSATION WITHOUT EVIDENCE
Use cautious phrasing: *"The ranking increased after this change. The change may have contributed, but the available data cannot establish causation."*

## 9. PRIORITIZE SEO WORK LOGICALLY
Organize findings as **Critical**, **High**, **Medium**, or **Low** based on SEO impact, affected pages, search visibility, technical severity, and effort required.

## 10. PROVIDE ACTIONABLE SOLUTIONS
Provide specific actions, affected URLs, and anchor text suggestions.

## 11. AI-GENERATED CONTENT MUST BE CLEARLY LABELED
Label generated titles, meta descriptions, FAQ ideas, and content suggestions as **"AI Suggested"**. Never auto-publish without user approval.

## 12. RESPECT TENANT ISOLATION
Bind every AI request strictly to the authenticated `user_id`, `project_id`, `website`, and selected `crawl_id`. Never mix data between tenants or projects.

## 13. RESPECT CRAWL SNAPSHOTS
When comparing crawls, use selected crawl snapshots only (`crawl_id`).

## 14. EFFICIENT LARGE WEBSITE PROCESSING
Pass aggregated, structured findings to the LLM rather than raw website HTML.

## 15. EXPLAIN SEO IN SIMPLE LANGUAGE
Answer: What is wrong? Why does it matter? What should I do? How important is it?

## 16. PROVIDE EVIDENCE-BASED OPPORTUNITIES
Base all content gaps, keyword opportunities, and internal linking suggestions on measured evidence.

## 17. HANDLE MISSING DATA CORRECTLY
When data is missing, output **"Data unavailable"**.

## 18. AI PROVIDER INDEPENDENCE
All AI features must execute uniformly across Ollama, Groq, OpenAI, Gemini, and Claude via the central `AIService`.

## 19. AI FAILURE MUST NOT BREAK SEO
The core SEO platform (crawling, technical audit, pages, keywords, rankings, backlinks, reports) continues working normally when AI providers are offline.

## 20. FINAL HIERARCHY
`REAL DATA` -> `SEO ENGINE` -> `EVIDENCE` -> `AI ANALYSIS` -> `AI RECOMMENDATION` -> `USER ACTION`.
